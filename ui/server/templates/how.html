00 — How this works

One plan, two signatures, one attested image.

The lab and the auditor negotiate an audit plan here. Both sign its digest. The plan is built into the box's image, and the running box proves it is executing exactly that plan.

static/ · the box
How logs come in and are verified, how a plan is run and bounded, how the image is built and attested. Fixed between agreements. Owner: Jonathan.
plan/ · the agreement
Six Python functions, one prompt, agreed settings and both signatures. Changes with every agreement. This UI edits only this folder.
ui/ · this app
A front end over the plan folder and the box's read-only endpoints. Not trusted: every digest comes with the command that reproduces it.

Check the UI without trusting it

Everything shown here is computed by the same code the box and CI run, and you can run it yourself from the repository root:

cd ui && uv run python -m aiab.plan_bundle digest ../plan      # the plan digest shown on the Sign screen
cd ui && uv run python -m aiab.plan_bundle check  ../plan      # the validation issues shown on the Plan screen
cd ui && uv run python -m aiab.plan_bundle verify ../plan      # the signature status shown on the Sign screen

Four digests, one meaning each

Plan digestHash of plan/ without tests/ and signatures/. This is what both parties sign. Shown on every screen.
Image digestThe container image, static part plus plan. Produced by the reproducible build; compared with the attestation measurement.
Release digestTinfoil's measurement of the release that launches the image. What the attestation verifier pins.
Policy digestThe box's effective settings manifest. Carried in every report.
