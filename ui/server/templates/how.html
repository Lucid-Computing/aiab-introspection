Auditor in a Box

Using LLMs to provide privacy-preserving and verifiable audits.

  1. The lab and the auditor agree on a plan here: a graph of the steps the box runs in order, from the logs of a run through Python steps, model steps and a classifier to the final report. Every save goes through the box's own loader, so a plan the box would refuse is never saved.
  2. Both sign the plan's digest with a signing key of their own. Each party has a root key, kept on its own machine, that certifies its signing keys once; the certificate travels with every signature. {% if settings.auditor_root_key %}On this prototype the server signs every version as the lab, and holds the auditor root: each auditor's browser makes a signing key of its own on the first Sign, and the server certifies it. Whoever controls the server can therefore sign as both parties. In the real version each party keeps its own root and signs on a page it controls, and the server holds no party's key.{% else %}The auditor signs in its own browser or on its own machine; the server never holds that key or the root. The lab's signing key and certificate may be on this server, in which case the server signs every version as the lab and whoever controls the server can sign as the lab.{% endif %} Any change after that voids both signatures.
  3. The box is a reproducible container image holding the box code and both parties' root public keys, and no plan. Anyone can rebuild it and check that the published image matches. A new signing key needs no new image; only a new root does.
  4. The image runs in a confidential VM on Tinfoil. The hardware encrypts its memory, so not even the server's operator can read what's inside.
  5. The chip signs a statement, checkable by anyone, of which image is running. Before each run the Runs screen compares it with the pinned release.
  6. The logging proxy signs the lab's recorded model traffic with its own key. A run sends those records and the signed plan to the box together.
  7. The box recomputes the plan digest, checks each party's certificate against the root built into its image and the signature against the certified key, applies its limits, and only then runs the plan over the records with the agreed model.
  8. Only a short report comes out. The logs are held only in memory, never written to disk, and dropped once the report is signed. The box keeps nothing of the plan either: every run brings its own.
  9. The box signs the report with its per-boot key, naming the plan digest, the image digest and the records it saw, so anyone can check it came from this plan and wasn't changed. The auditor checks it offline.
