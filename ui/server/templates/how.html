The three parts of AIAB
static/ · the box
How logs come in and are verified, how a plan is run and bounded, how the image is built and attested. Fixed between agreements.
plan/ · the agreement
One plan.json: the audit as a graph of steps (logs, Python, model calls, a classifier, the report) and both signatures. Changes with every agreement. The deploy slot: what the image is built from.
ui/ · this app
A front end over the agreement folders and the box's read-only endpoints. Not trusted: every digest comes with the command that reproduces it.

Check the UI yourself, without trusting it

Everything shown here is computed by the same code the box runs. From static/:

uv run python -m auditor.baked --folder ../plan digest   # the plan digest on the Sign screen
uv run python -m aiab.baked.check ../plan                   # the loader verdict on the Plan screen
uv run python -m auditor.baked --folder ../plan verify   # the signature status on the Sign screen
The words
Plan digestA fingerprint of the plan files, byte for byte. This is what both parties sign.
Image digestA fingerprint of the whole container image, box plus plan, from the reproducible build.
AttestationThe hardware's signed statement of which image is running. Comparing it with the published image digest proves the box runs what was built.
LockedA valid signature exists for this version, so edits are disabled. An edit would change the digest and void the signature.
