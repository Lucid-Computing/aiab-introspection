# Clean image reproducibility

`make image-reproducible` runs two clean builds of the current application source
and compares their OCI image-manifest digests. It requires Python 3, Bash 4+, Docker Engine,
`jq`, and a reviewed Buildx executable. The script copies Buildx into a new temporary
`DOCKER_CONFIG`, starts its own `docker-container` builder, and removes that builder
on completion/failure. It does not publish or replace `aiab:local`, change the user's
Docker config, or read `.env`. The Docker context remains an explicit runtime-source
allowlist.

The output directory contains `build-1.tar`, `build-2.tar`, and corresponding JSON
metadata. Retain these if you need independent review; they are not automatically
deleted. The image manifest covers the image config and layer digests. Comparing
this digest avoids confusing tar packaging timestamps with image identity.

Each export is inspected by `static/deploy/inspect_oci.py` without extracting files to
disk. Any `.pyc`/`.pyo` file or application `__pycache__` entry in any layer fails
the target. The pinned Python base contains 97 empty standard-library cache
directory entries; those directories are allowed, but any contents would fail.
The application layer contains no cache directories. `.dockerignore` re-excludes
directory descendants before selecting source files and puts global bytecode/cache
exclusions last, so directory reinclusion cannot carry host-generated bytecode.

## Temporary Buildx setup

If Buildx is not installed, download the binary and checksum list from the official
[v0.37.1 release](https://github.com/docker/buildx/releases/tag/v0.37.1). For Linux
amd64, this procedure keeps all files under a new `/tmp` directory and verifies
the checksum before making the binary executable:

```sh
aiab_buildx_dir=$(mktemp -d /tmp/aiab-buildx.XXXXXX)
curl -fsSL https://github.com/docker/buildx/releases/download/v0.37.1/buildx-v0.37.1.linux-amd64 \
  -o "$aiab_buildx_dir/buildx-v0.37.1.linux-amd64"
curl -fsSL https://github.com/docker/buildx/releases/download/v0.37.1/checksums.txt \
  -o "$aiab_buildx_dir/checksums.txt"
(cd "$aiab_buildx_dir" && rg ' \*buildx-v0\.37\.1\.linux-amd64$' checksums.txt | sha256sum --check)
# Continue only after checksum verification succeeds.
chmod 755 "$aiab_buildx_dir/buildx-v0.37.1.linux-amd64"
AIAB_BUILDX_BIN="$aiab_buildx_dir/buildx-v0.37.1.linux-amd64" make image-reproducible
```

The checksum authenticates consistency with the published checksum list; downloading
both still trusts GitHub/Docker's release distribution. The release also offers
signed checksums and provenance for stronger independent release review.

BuildKit's timestamp normalization and OCI exporter behavior follow the official
[reproducible-build controls](https://docs.docker.com/build/ci/github-actions/reproducible-builds/)
and [OCI exporter reference](https://docs.docker.com/build/exporters/oci-docker/).
The pinned BuildKit image digest was checked against the
[Docker Hub tag](https://hub.docker.com/v2/repositories/moby/buildkit/tags/v0.26.2).

## Signed audit executor (2026-10-15)

Source commit `c687463` was built with the same pinned toolchain above. Two clean
local OCI exports reproduced the CI-published digest exactly:
`sha256:2b28e0ca3e531af8b188105f274c4dfb878f80750fd7c9fc88d6c9a1e38e537b`.
Each passed inspection of 10,104 entries with no application bytecode/caches.
CI: https://github.com/Lucid-Computing/aiab-introspection/actions/runs/38702007153
Local transcript: `/tmp/aiab-audit-repro-final.log`.

File modes affect COPY layer digests: this workstation's default modes were 0664
for files and 0775 for directories, whereas CI checks out files as 0644 and
creates directories as 0755. Initial clean local builds agreed with each other
but differed from CI. Matching source modes (0644 for the included Python and
Markdown files, 0755 for their directories) reproduced CI. Independent builders
must use that checkout mode convention; timestamps alone do not normalize file
permissions. No runtime source change was needed.
